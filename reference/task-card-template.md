# 任务卡模板

统一身份、稳定 worker 协议和回执格式由 prepare 生成。每任务一份完整生效卡；变更整体替换，旧卡只留历史。
卡片写当前全部要求与可读原始资料引用，不写“继承旧任务卡/以下覆盖以上”；投递备注不另设一套要求。

```markdown
# <可独立验收的业务结果>
- 任务标识/卡片版本：<唯一 module；专业/角色可与其它任务相同，不表示复用agent>
- 整体目标与本卡作用：
- 精准入口/阅读地图：<实际工作目录；按顺序列文件#锚点、阅读目的和版本；必读/按需，不要求全仓摸底>
- 最小共享背景：<目标/边界索引；本卡相关的事实/契约/决策版本及片段；唯一维护者与变更通知方式>
- 失败尝试/未知项：<本卡相关尝试→证据→为何无效；尚未证实什么、谁核实，避免重复排查>
- 原始需求/追加消息：<路径、原文锚点与版本；数值、默认值、边界>
- 用户用例：<路径与承接锚点；逐项业务行为及预期>
- 范围与唯一写入负责人：<允许目录/文件、共享注册点归属>
- 依赖/契约：<版本、上下游、字段语义、错误、幂等与事务边界；分列开发前置/局部联调前置/最终验收前置，注明所需具体成果；无则写无>
- 结果负责人/独立验收者：<定位、授权内处理、自测、交接与相关回修的负责人；验收独立>
- 验收约定：<实现者提出、验收者审定的版本/证据；真实入口、可见预期、不通过条件与留证方式>
- 本阶段目标与完成门槛：<author/execute/实现；必需入口/判断不能留待接入>
- 早期真实探路（适用时）：<最小真实输入、贯通步骤、最终产物和判断、扩大条件>
- 最终完整范围：<数量/场景/数据范围；小样本不抵扣未执行项>
- 分层验证与交接：<本模块定向正反例及SHA；与哪些真实服务/决策融合、前置/负责人/放行证据；最终完整链路归属；有页面用真实页面>
- E2E 范围/预算：<spec/组，开发默认≤6个且≤15分钟；超预算交统一回归>
- 环境：<真实启动命令/URL、账号数据、端口/数据库隔离、共享锁与恢复方式>
- 证据：<逐例报告、截图/trace目录、SHA；非页面任务说明理由>
- 交接重点：<已定方案、真实未知项、接续所需资产；项目已有L1/L2则沿用其追溯>
- 执行者选择：<新成果新module/agent；同结果关联回修优先reuse及理由；fresh的实际收益、旧者停止证据和原资产交接>
```

只在本次提供或指定 demo/截图等资料时，补充具体参考区域、状态、保留与变更要求。
研究任务补充来源核实、口径和能改变结论的反例；不要把实验样本变成通用功能硬编码。
派发前核对来源可读、要求有用例、文件归属不冲突、依赖可满足；验收卡覆盖跨模块完整流程。
完成条件未由独立验收者审定，不启动该结果的实现；可先做不依赖该约定的只读探路。
其它结果已具备审定条件和独立写入范围时分别放行，不因某块未定就全体等待。
独立新工作另建任务；任务未结束时不连续投递新目标。只读调查卡需写明问题解决的后续负责人和授权边界。
