# 交付与长任务

## 持久事实与唯一当前快照

沿用项目已有文档结构，保存三类资产：

- 原始需求、追加/纠正原文与附件版本，方案/契约、决定理由及未知项；不只存模型改写的摘要。
- 用户用例：每条要求映射业务行为、负责人、验收者、操作/预期与证据；遵守项目锚点规范，不强造 L1/L2。
- CURRENT.md：唯一当前快照，链接上述资产，列阶段/依赖、真实 host/thread/attempt、集成 SHA、验收 SHA、
  当前失败与未决输入、下一步。用 snapshot 整体替换，旧快照自动归档，禁止并列多版“覆盖以上/下方”。

每次派发、收回执、需求/契约变更、回修和阶段切换更新快照。待处理问题按真实身份+turn/request ID 去重，
缺 ID 则按原问题指纹；保留原问题/来源、影响、首次时间、处理人、open/answered/resolved 和答案证据。
answered 只是已答，真实恢复后才 resolved；不要靠 cursor 变化生成重复问题。
压缩/接手后：CURRENT→本卡→相关原始要求/资料→用例/契约→最新回执与 Git，随后监督全部线程。

## 真实探路与扩大

长异步流程、外部研究、批量模型调用或跨模块未知较大时，在批量扩张前先做最小真实纵向试跑。
选能暴露关键风险的少量真实对象，贯通入口、实际执行、最终产物和业务判断；记录输入体量、真实终态、
失败与关键缺证。结构校验、accepted、固定响应、零实际研究不能作为业务成功。
出现输入过大、结果空缺、外部证据未取到或核心判断未执行时，先修链路，再扩大相同风险路径。
不依赖此结果的工作照常并行；同一个开发卡可先试跑再扩张，无需机械增加多张探路卡。
最终仍按用户完整数量、数据和用例验收，明确小样本覆盖哪些项、哪些尚未执行，不能缩减最终范围。

## 会话接续

主端不加载全部源码和完整日志；worker 提交结论、来源、证据链接与未知项。
先 collect 精简回执并收存同 attempt handoff，只在异常/无回执/输入/证据冲突时读对应会话。

同阶段短修复可 reuse。阶段切换、目标变化、反复重探索/遗忘约束或旧假设混杂时，在旧 turn 结束后 fresh：

1. 用宿主快照确认**目标旧线程**已结束；running、未知、待审批/输入先解决，归档不代表停止。
2. 核对交接完整，保存原始需求/用例/契约、成果 SHA、环境、当前失败、下一步；collect 后持久化。
3. reply --session fresh 带真实旧 session ID 与终态，生成新 attempt；用原生创建，沿用原模块和已有 worktree，
   绑定新身份，历史记录保留。工作树脏内容也必须交接，不覆盖、不重建、不自动清理。
4. 当前模型/深度显式继承；不设新压缩阈值，不按压缩次数自动中断。短回修不为“清上下文”反复冷启动。

CLI 不能验证宿主终态是否真实，主端必须实际取快照。新旧线程不能同时写同一 worktree。
主会话也不必无限累积历史；用户决定移交主会话时提供 CURRENT 与资产索引，不把换新当成自动创建用户会话的授权。

## 验收与测试分工

派实现前生成用例，每条含来源、目的、前置身份/数据、逐步操作与可见预期、最终状态/副作用、负责人和证据。
核心流程用连续数据从入口跑到最终结果；分支按角色/状态/条件列决策表，覆盖相关默认值、边界、权限与异常。
写入验证重复点击/重试/刷新/消息幂等；事务/异步验证部分失败、超时未知、恢复/补偿、取消及适用并发不变量。
导入/下载/打印还要核实际产物内容，不止检查按钮或请求成功。

开发各跑相关最小自测，E2E 默认≤6 spec且≤15分钟。超预算交统一回归，不各自扩全量。
主端在全部相关合入后，用 e2e-scope plan 合成已登记范围与集成 diff，去重后统一执行一次。
公共 schema/迁移/seed、共享基座/鉴权/全局配置、跨≥3模块的数据流，或项目发布规范要求时升级全量并记录理由。
verify/regression 可同一独立 worker 分阶段承担，保留需求视角的独立验收；并行 author 提前准备脚本缩短尾部等待。
环境修复集中交给明确负责人，避免各 worker 重复修。共享数据/生成客户端无法隔离时持锁串行。

独立验收在最终集成 SHA 启动真实服务；有页面就实际操作页面，不 mock 自家业务 API 充当集成通过。
API/数据库可准备非被测前置数据、注入受控故障及核副作用。确无页面的 CLI/研究需求说明原因，验证实际入口；
有页面但不可用是 blocked。给定 demo/原型须实际查看对应区域与状态，未经指定不强行索取 demo。

逐例记录：来源/用例→实际操作→结果→passed/failed/blocked/not-run→脱敏截图/trace/报告→SHA/环境→缺陷负责人。
当前失败如实保留，不能改预期、删断言或移到 risks 取得 done。修复前失败存 resolved_failures，与当前未解决失败分开。
只改回执格式、补交接且代码/环境/基线不变时，重校协议即可，保留原有效证据；发生变化才按影响范围复测。
最终复测失败项、受影响分支及完整主流程；后续合入使证据过期时更新，不沿用旧 SHA 的“全部通过”。
最终报告覆盖数、失败/阻塞/未执行、验收版本和证据位置，所有必需项通过才称完成。
