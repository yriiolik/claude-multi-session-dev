# v2 任务卡模板

默认每张卡拥有可验收的业务结果和明确文件范围；粒度规则见 delivery-quality.md。
模型、权限和派发命令以 SKILL.md、v2-commands.md 为准。worker 不需要加载编排技能。
主端填写后通过 `cc-fleet prepare --task <绝对路径>` 生成统一身份和回执前缀。

```markdown
# 任务：<可独立验收的业务结果>
- RQ / module / role：<实际值，role 与 prepare 一致>
- 整体业务目标：<完整流程及本卡作用>
- 范围：<允许改动目录/文件，包含共享文件与注册点的唯一负责人>
- 不做：<边界，避免顺手扩展>
- 依赖与流程负责人：<上下游、阶段、端到端负责人>

## 原始需求
- 原始来源：<可访问路径及章节/版本，包含相关原文、数值、默认值、禁止行为>
- 需求/方案资产：<路径与锚点>
- 参考资料（仅本次提供或指定时保留此行）：<资源路径、相关区域/状态、保留与变更项>
- 用户用例：<派发前生成的路径、由本卡承接的每条用例锚点>
- 完整主流程：<路径/步骤，本卡的输入与输出>

## 契约与实现约束
- 契约：<版本/路径、字段语义、错误、幂等键和事务边界（适用时）>
- 接口提供方/消费方：<真实名称，无依赖则写无>
- 决策：<已定方案和理由、未知项；禁止单边改共享契约>
- 文档追溯：<遵守项目现有 L1/L2 等规范，无此规范不强造>

## 验证与环境
- 验收行为：<逐条关联用户用例，不能只列函数/测试名称>
- 开发自测：<相关单测/API/页面测试、预期结果>
- **E2E 范围（必填）**：<本卡允许跑的 spec 文件/组，≤6 个且预计 ≤15 分钟；写“全量”须附理由。
  主端填不准时写“按 cc-fleet-e2e-scope suggest 推导并在回执登记”，但仍受预算上限约束。
  跨模块/全量回归不写在开发卡里，由主端落地后单独派回归卡。>
- 独立页面验收：<完整主流程、分支异常；有指定参考资料时核对相应内容；verify 卡逐项操作全部适用用例>
- 环境：<集成基线、真实页面 URL/启动命令、测试身份/数据、隔离与锁、配置恢复方法>
- 证据：<持久化报告目录，逐例实际结果、截图/trace、commit SHA>
- 非页面需求：<仅确无页面入口时写不适用原因和实际入口验收方式>

## 回执
按统一前缀 JSON 回执，附逐用例完成/未完成映射与证据路径。
开发提交并通过 cc-fleet-land 合入；verify/integ 不修改业务代码，报告实际验收 SHA。
失败如实填 failed，阻塞如实填 blocked；不得把失败藏到 risks 或伪装 not-run 以取得 done。
压缩/恢复后先重读本卡、原始需求、用例、契约及最新状态，再继续。
```

主端派发前检查：来源可读、每项需求有用例、范围与公共前缀一致、依赖可满足。
验收卡必须覆盖跨模块完整流程，不以各开发卡自测汇总替代。发现缺陷回派相应开发卡。
